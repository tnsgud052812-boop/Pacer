# 🚶 Pacer 만보걷기 자동 크롤러

캔탑스 만보걷기 데이터를 Cloudflare에서 **매시간 실행**하여 수집합니다. 한국 시간 자정 이후 실행에서 전날 통계를 정리합니다.

## 걸음수 집계

`index.html`은 같은 배포 위치의 `data/` 파일을 읽습니다. 로컬 확인은 저장소 루트에서 `python -m http.server`로 웹 서버를 실행합니다. 배포 시 HTML과 수정된 데이터 파일을 함께 반영해야 합니다. 월 목록은 크롤러가 생성하는 `data/months.json`을 사용합니다.

- 매일 API 측정 누적값과 **전날 스냅샷의 측정 누적값**의 차이를 계산합니다.
- 시간별 파이프라인은 월이 다른 측정값을 차감하지 않습니다. 월 전환이 확인되지 않은 값은 미확정으로 남깁니다.
- 월 초기화는 별도 보정 기록 또는 전체 변화로 판단합니다. 최소 5명의 비교 가능한 자료 중 60% 이상이 감소하고 이전 달 기준점이 남아 있으면 초기화 후보로 기록합니다. 후보에 해당하는 개인의 첫 새 달 누적값은 잠정 기간 누적분이며 실제 당일 걸음수는 `N/A`입니다. 이후에도 추정 상태를 표시합니다.
- 월별·시즌별 통계는 일별 증가분과 포함 가능한 기간 누적분을 합산합니다. 시즌 시작 전 활동까지 포함한 기간 누적분은 시즌에 전부 포함하지 않고 미확정으로 남깁니다. 같은 날 재실행해도 중복 합산하지 않습니다.
- 일별 CSV의 `월간누적`은 API 측정 원본, `월집계누적`은 일별 차이의 합계입니다. `latest.csv`의 `월누적`과 개인별 파일의 `월누적`은 합계이며, `latest.csv`의 `측정누적`은 원본입니다.
- 측정 간격에 발생한 증가분을 측정 날짜에 귀속합니다. 앱 동기화 지연으로 실제 활동 날짜와 차이가 날 수 있으며, 전날 자료가 없는 날은 정확한 차이를 복원할 수 없습니다.
- 확인된 예외는 `data/statistics_corrections.json`에 기록해 재계산에도 유지합니다. 2026년 10월 1일은 `N/A`로 제외하고, 10월 3일에 확인된 초기화 이후 누적값을 합계에 반영합니다. 해당 값에는 앞선 날짜의 걸음수가 포함될 수 있으므로 3일 하루의 실제 활동량으로 해석하지 않습니다.

기존 저장 통계 재계산(네트워크 요청 없이 `data/` 갱신):

```sh
python rebuild_statistics.py
```

회귀 테스트:

```sh
python -m unittest discover -s tests -v
```

## 시간별 원본과 자정 집계

Cloudflare에서는 기존 `.github/workflows/crawl.yml`의 `workflow_dispatch`를 **main ref**로 매시간 호출합니다. 권장 실행은 매시간 정각이며 자정(한국 시간 00시) 실행도 포함합니다. GitHub Actions 내부 예약은 추가하지 않았습니다. workflow 파일 경로는 그대로입니다.

워크플로는 `python hourly_pipeline.py`를 실행합니다.

- **measurements 브랜치:** `raw/YYYY/MM/DD/<실제수집시각>_<실행ID>.json.gz`에 페이지별 응답 본문, 수집 시작/종료 시각, 측정값, 성공/실패를 추가합니다. 부분 실패도 기록하며 원본은 덮어쓰지 않습니다. 동명이인이 있어도 전체 수집은 성공 처리하고 원본의 모든 행을 보존합니다. 중복된 이름만 집계를 보류하며, 다른 사람의 집계는 계속합니다. 계정을 구별할 식별자가 현재 리더보드 응답에 없어 순위나 걸음수로 임의 선택하지 않습니다. 이전 버전의 중복 이름 실패 원본도 모든 페이지의 수집 완료가 확인되면 재사용합니다.
- **변경 추적:** 정상 원본의 `changes_since`와 `changes`에서 마지막 정상 관측 이후 누적값이 바뀐 사람과 전후 값을 확인합니다. 실제 업로드 시각을 단정하지 않고 변화가 관측된 시간 구간을 확인할 수 있습니다.
- **하루 기준점:** 자정 이후 실행에서 전날 안에 수집을 시작하고 완료한 마지막 정상 원본을 선택합니다. 예를 들어 10월 9일 00시 실행은 10월 8일 23시 정상 원본을 선택합니다. 9일 00시 원본을 전날 값으로 사용하지 않습니다.
- **늦은 실행:** 자정 실행이 빠져도 다음 실행에서 종료 날짜를 순서대로 보충합니다. 현재 날짜는 집계하지 않습니다. 날짜 마지막 정상 수집이 자정에서 90분 이상 떨어지면 잠정으로 표시합니다.
- **main 브랜치:** `data/checkpoints/YYYY-MM-DD.json`에 기준점 원본 경로/커밋/측정 시각/개인별 상태를 기록하고, 일별·개인별·월별·시즌별 통계와 `data/checkpoint_status.json`을 갱신합니다. 통계 변경이 있을 때만 main에 커밋하고 기존 브랜치 기반 GitHub Pages에 빌드를 요청합니다.
- **기간 누적분:** `data/adjustments/YYYY-MM-DD.json`에 별도 기록합니다. 일별 CSV의 `집계반영분`은 합계 계산용이고 `오늘걸음수`와 다를 수 있습니다. `집계상태`가 confirmed가 아니면 잠정 또는 미확정 자료입니다. 며칠 수집이 빠진 경우 증가분을 특정 하루 활동으로 표시하지 않습니다.
- **장애:** 오늘 수집이 실패해도 실패 원본을 보관하고 이전 정상 원본으로 종료 날짜 집계를 진행합니다. 집계 중 오류가 나면 공개 데이터에 일부 집계만 반영하지 않습니다. 원본 push와 main push가 경쟁하면 강제 push하지 않고 실패합니다.

정각 실행의 하루 증가분은 일반적으로 전날 23시부터 당일 23시까지의 측정 변화입니다. 실제 00~24시 활동량으로 해석하지 않습니다. 앱 동기화 지연과 월 초기화 추정이 있는 경우 통계 화면에도 미확정 상태를 표시합니다. 사용자 비교 키는 현재 이름이며, API 응답에 포함된 식별자는 원본 본문에 보존합니다.

특정 날짜의 변화·실패 현황 조회(원본 브랜치 읽기만 수행):

```sh
python hourly_pipeline.py --report 2026-10-08
```

기존 `rebuild_statistics.py`는 시간별 파이프라인의 체크포인트가 있는 날짜를 구형 계산으로 덮어쓰지 않습니다. 체크포인트를 바꾸는 보정은 원본을 근거로 별도 검토해야 합니다.
